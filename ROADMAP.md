`torrents/info` (filter, category, tag, hashes, sort, reverse, limit, offset) with every field the apps parse; `properties`, `files`, `trackers`, `add` (urls: magnets, info hashes, .torrent URLs fetched with `VpnFetch` - queued while locked; `torrents` multipart; category, savepath, paused / stopped, tags, sequentialDownload, firstLastPiecePrio accepted, ratioLimit, seedingTimeLimit), `delete` (deleteFiles = Recycle Bin), `pause` / `resume` / `stop` / `start`, `setForceStart`, `recheck`, `setLocation`, `setCategory` (409 if unknown), `createCategory` / `editCategory` / `removeCategories` / `categories`, `setShareLimits`, `top` / `bottom` / `increase` / `decreasePrio`, tags, `transfer/info`, `sync/maindata` (always full). 403 before sign-in, 405 for actions by GET, "Ok." / "Fails.". **States** (`QbitApi.QState`): VPN-locked / game / queue = `queuedDL` (never failed), `metaDL`, `checkingDL`, `downloading` / `stalledDL`, `pausedDL`; | 1.3 | Search, done properly (Search.cs, SearchPage.cs). **Indexers via Torznab only** - your own Prowlarr (`/api/v1/indexer` -> each torrent indexer's `<base>/<id>/api`; Usenet skipped), Jackett (`t=indexers&configured=true` on the `all` endpoint -> `/api/v2.0/indexers/<id>/results/torznab/api`; falls back to `all` on an old Jackett) or single Torznab feeds; no built-in site list, no scraping. API keys DPAPI-protected (CurrentUser + own entropy, `Secret`) in `search.json`, redacted from every message / log (`Torznab.Redact`). `t=caps` per feed (search / tv-search season+ep / movie-search imdbid+tmdbid, categories); `t=tvsearch` (season, ep), `t=movie` (imdbid), `t=search` with words as the fallback; categories 2000 / 5000 / 3000 / 1000+4050 / 4000 / 7000 / 8000; `extended=1`; `<error code>` read (100-102 = key refused). **Over the VPN only:** `VpnFetch.Fetch` (new: one request, socket bound to the VPN IP, DNS over the VPN, redirects NOT followed so a download link that redirects to `magnet:` is caught; `BoundHttp.Create(..., redirects)`); while locked a search returns `Locked` without a single request. **Parallel:** every enabled feed at once, per-feed timeout (`SearchProfile.TimeoutSec`, 15 s), status ok / timeout / error / locked with ms; reliability per feed (ok / fail, decayed). **Ranking** (`Ranker`): `Parse` reads resolution, source (CAM / TS / TC / SCR = `Low`), codec, HDR / DV, audio, group, season / episode (Media.Parse); `Score` = health (20 log10(1+seeders), peers) + profile (resolution distance, source rank + preferred, codec) - avoided words (-300) - low (-150) - over max GB (-120) + size sanity vs `ExpectedMin` (MB/min by resolution, x265 halves, runtime 45 / 100 min) + 20 x reliability; `Flags` = a program in the file list (.scr / .lnk always; .exe etc. for video / music), a name ending like a program, password-archive hints, < 1/4 of the expected size, published < 3 h with >= 1000 seeders, codec-pack names; `Rank` = flagged last, then score; duplicates by info hash once. Optional / on-click **Check files** fetches the .torrent and re-flags. Already in the list / grabbed by RSS marked. **Search page:** query (`show s01e02` -> tvsearch, `tt...` -> movie), per-indexer pills, filters (quality, category, size, seeders, indexer, show flagged), sort by score or any column, score breakdown, Download (normal Add window: VPN lock, Defender, categories), Add to RSS rule (`SearchEngine.RuleFrom`), Indexers and Ranking windows. **Pipe:** `search <words> [--n N] [--cat c]` -> top N JSON (`SearchEngine.Json`), `search-add <id> [--category c]`; `--cmd` waits 45 s for `search`. status.json `indexers` (count). Tests: local Torznab stand-in (Prowlarr + Jackett, fixtures: good, CAM, fakes, wrong sizes, a slow and a failing indexer, a redirect to a magnet), ranking order, flags, parallel timeouts, every request from the VPN stand-in, nothing while locked, key encryption, download from a result into the local swarm, the pipe from a test copy; all 1.0-1.2 tests. |

Never for trackers, peers, DHT, RSS, blocklists or public hosts. UI: "Local server - not through VPN (private address)" (Search status, Indexers window, web page). **Pipe for Hallow Remote** (Remote.cs, `RemoteApi`): `list` (name, progress, speeds, state + `status` code, category, size, eta, peers, ratio, paused, complete, flagged, `vpnLocked` per torrent and overall, held / game), `stats` (session / all-time), `pause <hash>` / `resume <hash>` (8+ hex prefix), `add ... --direct`; REMOTE-CONTRACT.md. **Web interface** (WebUi.cs, src\WebUi\ embedded): `/ui/` on the same `ApiServer` (`Settings.WebUiOn`, off by default, only while the Web API runs; same bind rules, allow-list, sign-in, ban), `/ui/api/` session / login / logout / list / stats / status / categories / add (magnet or multipart .torrent, direct) / pause / resume / category / search / search-add / connect-vpn (Hallow VPN `connect fastest`); CSRF = Origin / Referer check + `X-CSRF-Token` (HMAC of the SID with a per-run secret) on every POST; CSP `default-src 'none'; script-src 'self'; style-src 'self'...; frame-ancestors 'none'`, no inline script or style, no external resources; light / dark (prefers-color-scheme + a toggle). `ApiResponse.Headers`, `QbitApi.CrossSite` / `SignIn`. **Headless** (HeadlessHost.cs): `--headless` and HallowTorrentsHeadless.exe (headless\Program.cs + every non-window source; no WPF / WinForms / System.Drawing reference) - Core, RSS, search, VpnWatch, the pipe, the Web API / web interface, game check, watch folder, Defender, status.json (`headless`, `webUi`), headless.log; the app's single-instance mutex; `Games`, `Scheduler`, `Fmt` moved to Games.cs, the version to BuildInfo.cs. ## Later

| Idea | Why it isn't in yet |
|---|---|
| "Play while downloading" button that opens the player | It has sequential download; it never opens files by itself, so playing is up to you. |
| Port forwarding through a VPN that offers it | NordVPN doesn't; UPnP on the home router would bypass the VPN, so it stays off. |
| Bind local peer discovery to the VPN | LPD is multicast on the home network; it's off by default instead. |
| v2 / hybrid torrents in the creator | 1.1 makes v1 torrents (what every client and tracker understands). |
