# Hallow Torrents roadmap

## Done

| Version | What |
|---|---|
| 1.0 | MonoTorrent 3.0.2 (MIT) engine. VPN required with no override: Hallow VPN's status.json / pipe (`connected`) plus its adapter, or a picked adapter (NordVPN app, WireGuard...); every socket bound to the VPN IP (peer listener, outgoing peers via a bound ISocketConnector, DHT endpoint + a DHT bootstrap that resolves its routers over the VPN, HTTP(S) trackers and web seeds via StandardSocketsHttpHandler's ConnectCallback with our own DNS-over-the-VPN, UDP trackers via our own bound BEP 15 client), IPv6 peers refused, UPnP / NAT-PMP off; the VPN re-checked every 250 ms and the engine stopped and disposed within 1 s when it drops or its IP changes, rebuilt when it's back; "Connect Hallow VPN" (`connect fastest`); optional "Check my torrent IP" (ipleak.net, on click). Add .torrent / magnet (window, drop, pipe `add`, double-click after you allow the per-user handler), file picking and priorities, save folder, queue, pause / resume, global / per-torrent / scheduled speed limits, ratio and seeding-time limits, per-category ratio goals and folders, DHT / PEX / LPD switches, encryption prefer / require, sequential download, super-seeding, force recheck, watch folder, IP blocklist (eMule / P2P). Game-aware pause or limit (Delta Force, Discovery, Hub's playing, own list). Defender scan of finished downloads at Idle priority, suspicious-file flags, never opens files. Media library hand-off (copy or move-and-seed) with Jellyfin names. Family link, status.json, Hub tray host, accent, light / dark, crash reports, updater. Local-swarm tests including leak tests. |
| 1.1 | Closing the gaps with qBittorrent. **RSS auto-download** (Rss.cs): feeds with their own interval, fetched only over the VPN (VpnFetch = BoundHttp: socket bound to the VPN IP, DNS over the VPN; nothing while locked); rules with must / must-not (words, `|`, `*`) or regex, feeds, category, save folder, prefer (1080p) / avoid (CAM, TS...), add paused; episode tracking (SxxEyy, 1x02, dates, season packs, movie + year) across all rules, never twice; optional upgrade to a better quality within N hours (old one leaves the list, files to the Recycle Bin); a live preview in the rule window; rss.json. **Torrent creator** (Creator.cs, MonoTorrent's TorrentCreator): file or folder, auto / manual piece size, tracker tiers, web seeds, private, comment, source; seed straight away (never treated as a finished download). **Editing:** add / remove / edit trackers (kept per torrent, re-applied on every engine build, always created through Net.BoundTracker), rename files and folders and move storage (Entry.Paths, through the engine or on disk while locked, re-applied on rebuild; the move-to-library hand-off is now remembered too), all-files priority. **Blocklist from a URL** (Blocklist.cs): P2P / eMule .dat / CIDR, plain, .gz or .zip, downloaded over the VPN every N days, swapped in live, ranges shown. **Statistics** (Stats.cs, stats.json): session / all-time down and up, ratio, time seeding, time locked by the VPN, peers blocked. Pipe `add <magnet> --category <c>` for Hallow Browser. Tests: local RSS / blocklist web stand-in (requests only from the stand-in VPN address), creator round trip, tracker edit, rename, move storage, blocked peer refused, stats persist; all 1.0 tests incl. leak tests. |
| 1.2 | Works with Radarr / Sonarr / Prowlarr: a **qBittorrent-compatible Web API v2** (WebApi.cs), written from Radarr's / Sonarr's `QBittorrentProxyV2` and selector. Hand-written HTTP/1.1 on a `TcpListener` (keep-alive, `Expect: 100-continue`, chunked, multipart; HttpListener would need admin off localhost). Endpoints: `auth/login` / `logout` (SID cookie), `app/version` (v4.6.7), `webapiVersion` (2.9.3), `buildInfo`, `preferences` (save_path, queueing, max_ratio*, max_seeding_time*, max_inactive*, max_ratio_act 0, dht...), `defaultSavePath`, `setPreferences` (accepted, ignored); `torrents/info` (filter, category, tag, hashes, sort, reverse, limit, offset) with every field the apps parse; `properties`, `files`, `trackers`, `add` (urls: magnets, info hashes, .torrent URLs fetched with `VpnFetch` - queued while locked; `torrents` multipart; category, savepath, paused / stopped, tags, sequentialDownload, firstLastPiecePrio accepted, ratioLimit, seedingTimeLimit), `delete` (deleteFiles = Recycle Bin), `pause` / `resume` / `stop` / `start`, `setForceStart`, `recheck`, `setLocation`, `setCategory` (409 if unknown), `createCategory` / `editCategory` / `removeCategories` / `categories`, `setShareLimits`, `top` / `bottom` / `increase` / `decreasePrio`, tags, `transfer/info`, `sync/maindata` (always full). 403 before sign-in, 405 for actions by GET, "Ok." / "Fails.". **States** (`QbitApi.QState`): VPN-locked / game / queue = `queuedDL` (never failed), `metaDL`, `checkingDL`, `downloading` / `stalledDL`, `pausedDL`; finished = `checkingUP` until Defender's scan is done, `error` if flagged / threats (never imported), `uploading` / `stalledUP`, `queuedUP` while locked, `pausedUP` when paused or at the seed goal. **Categories** = Hallow categories (created on first use, no hand-off); `content_path` = `Core.RootOf`; an app's torrent (`Entry.Api`) is never moved to the library before import; per-torrent share limits (`Entry.ShareRatio` / `ShareMinutes`, `Plan.Item.RatioCap` / `SeedCap`; -2 global, -1 none). **Security:** off by default; PBKDF2 password hash; sessions expire after N idle minutes; 5 wrong passwords / 15 min = 15 min ban; CSRF (Origin / Referer vs Host = 401); one bind address - 127.0.0.1 default, LAN / Tailscale by choice, never 0.0.0.0, public or the VPN IP; public remote addresses always refused; optional allow-list. New **Radarr / Sonarr** page (on / off, address, port, sign-in, allow-list, categories, how to connect). status.json `webApi`. Tests: contract suite replaying the apps' request sequences over real HTTP on 127.0.0.1 with the local swarm (download through the stand-in VPN, `stalledUP` / `pausedUP`, content_path for folder and single-file torrents, URL fetched only after the VPN is back), auth / ban / expiry / CSRF / allow-list / bind tests, 1.2 leak check; all 1.0 / 1.1 tests. |

## Next (planned)

| Version | What | Where to plug in |
|---|---|---|
| 1.3 | Search through Prowlarr / Jackett (Torznab) with smart ranking. | Requests to indexers go through `VpnFetch.Get` (or `BoundHttp.Create`) like RSS; parse with the same XML approach as `RssParse`; rank with `RssMatch.Quality` / `RssMatch.Avoided` / `RssMatch.Key` (dupes vs. what's in the list and `Rss.Data.Grabs`); add with `Core.AddMagnet` / `AddTorrentBytes`. Prowlarr can already *send* to Hallow Torrents through the 1.2 API; for searching *from* Hallow, keep the Prowlarr / Jackett URL + API key in settings (the key is a secret: protect it with DPAPI like Hallow VPN, never in settings.json in the clear). |
| 1.4 | Phone / web UI and a NAS / headless mode. | Reuse the 1.2 server: `ApiServer` (listener, keep-alive, multipart, allow-list, public-address refusal) and `QbitApi` (`Route` switch - add new paths there, or a second handler behind the same `ApiServer`; `ApiGuard` for sign-in / sessions / ban; `QbitApi.Torrent` / `QState` for the list JSON). Serve the pages as embedded resources from a new `/ui/` prefix with the same SID cookie (and keep the CSRF check). A NAS / headless mode = `TorSettings.Headless` + the `Controller` without windows (the tests already run it), with the Web API on a LAN / Tailscale address. Never relax the VPN lock or the bind rules (`ApiGuard.BindProblem`). |

## Later

| Idea | Why it isn't in yet |
|---|---|
| "Play while downloading" button that opens the player | It has sequential download; it never opens files by itself, so playing is up to you. |
| Hallow Remote control | The pipe already has `status`, `add`, `pause-all`, `resume-all`; Remote can show it later. |
| Port forwarding through a VPN that offers it | NordVPN doesn't; UPnP on the home router would bypass the VPN, so it stays off. |
| Bind local peer discovery to the VPN | LPD is multicast on the home network; it's off by default instead. |
| v2 / hybrid torrents in the creator | 1.1 makes v1 torrents (what every client and tracker understands). |
